# DoctorPresso AI Engineer — CareFlow V3 Gap Analysis

기준일: 2026-09-04

이 문서는 공개 채용공고의 기술 요구를 CareFlow 코드와 연결하기 위한 내부 검증표다.
실제 환자 데이터·임상 성능·전문의 검증을 했다고 주장하지 않는다.

| 공개 업무/역량 | V2 상태 | V3 대응 | 증거 |
| --- | --- | --- | --- |
| EMA + Text 멀티모달 분류 | 없음 | synthetic fusion baseline | `ai/lab.py` |
| Vector DB | 없음 | Qdrant local/server compatible index | `ai/lab.py` |
| Reranker | 없음 | deterministic smoke reranker | `ai/lab.py` |
| LangGraph | 없음 | retrieve/context graph | `ai/lab.py` |
| RAG 평가 | 없음 | Recall@5 / MRR / nDCG@5 | `ai/lab.py` |
| SFT | 없음 | Qwen2.5 + QLoRA script | `ai/posttrain.py` |
| DPO | 없음 | preference dataset + DPOTrainer script | `ai/posttrain.py` |
| LLM-as-a-Judge | 제한적 | rule gate + 외부 judge 확장 지점 | `ai/lab.py` |
| ML pipeline | 서비스 중심 | synthetic data→train→eval→gate | `ai/lab.py` |
| PyTorch | CareFlow 내 없음 | training requirements + post-training | `ai/requirements-training.txt` |
| sklearn / NumPy | CareFlow 내 없음 | baseline/evaluation | `ai/lab.py` |
| EMR/설문 질환 예측 | 없음 | 구조만 synthetic으로 검증 | 실제 임상 성능 미주장 |

## 채택 게이트

### RAG
- Dense / lexical / hybrid+reranker를 같은 holdout에서 비교
- Recall@5, MRR, nDCG@5
- 전체 embedding/reranker 실험은 smoke 통과 뒤 실행

### SFT / DPO
- Base / SFT / SFT+DPO 같은 holdout
- groundedness / safety / format / hallucination / latency
- SFT 또는 DPO가 회귀하면 서비스에 채택하지 않음

### Multimodal
- EMA-only / Text-only / Fusion 비교
- ROC-AUC / F1 / Brier
- synthetic 결과는 임상 성능으로 해석하지 않음

### Evaluation
- deterministic contract gate
- optional LLM-as-a-Judge
- 전문의 평가가 없는 상태를 명시
