## 2. 운영·유지보수 증거

CareFlow의 마지막 완성 과정에서는 기능 추가보다 **실제 배포에서 결함을 발견하고 재발 방지 계약으로 고정한 경험**이 더 중요합니다.

### Runtime packaging failure → 수정

첫 Render 배포에서 기본 `DATABASE_URL=sqlite+aiosqlite` 경로를 사용하면서 `aiosqlite`가 dev extra에만 있어 startup이 실패했습니다.

수정:
- `aiosqlite`를 default runtime dependency로 이동
- lockfile 갱신
- default SQLite configuration과 driver dependency를 묶는 regression test 추가
- Render에서 `pip install .` 재빌드 후 서버 startup 확인

### Evidence section overlap → 수정

live smoke에서 다음 Plan 문장이 Objective evidence에도 들어가는 의미 오류를 발견했습니다.

```text
다음 주에 수면 기록을 함께 확인할 계획입니다.
```

`확인` 토큰이 Objective heuristic에도 매칭되어 `O:[3,4]`가 되었고, Plan chunk를 먼저 분류한 뒤 Objective 후보에서 제외하도록 수정했습니다.

최종 live synthetic contract:

```text
S: [1,2]
O: [3]
P: [4]
state: READY
transcript: purged
audit: session.finalized + transcript.purged
```

이 시나리오는 `scripts/deployment_smoke.py`와 regression test에 고정되어 `main` 배포마다 다시 확인됩니다.

## 4. 백엔드 중심 기술 증거

### API / contract

- strict Pydantic request/response schema
- idempotency key
- sequence duplicate rejection
- explicit session state transitions
- evidence sequence tracing
- review/edit/approve path
- purge endpoint and audit trail

### Data / lifecycle

- PostgreSQL-oriented async SQLAlchemy model
- Alembic migration
- Redis Hash + TTL transcript path
- 성공/검토 후 raw transcript purge
- public demo에서는 runtime backend를 `/v1/operations`에서 사실대로 노출

### Realtime

- WebSocket text/binary ingest
- browser utterance-unit audio path
- optional faster-whisper recognition
- continuous partial ASR이라고 과장하지 않음

### Operations

- Docker image build
- GitHub Actions unit/lint/type/migration
- PostgreSQL 16 + Redis 7 integration
- Public Readiness / Gitleaks history scan
- Render auto-deploy
- production URL 대상 Deployment Smoke

## 5. AI는 보조 증거로 사용

백엔드 지원에서 아래 실험을 메인 스토리로 앞세우지 않습니다. 핵심은 **AI 결과를 서비스 계약·평가·회귀 방지로 연결한 방식**입니다.

- RAG: full semantic 경로가 현재 synthetic regression set에서 smoke hybrid보다 낮아 **미채택**
- SFT: reference-token F1 `0.0648 → 0.1244`, unsafe `0 → 0`, unsupported-number `0 → 0` → **adopt**
- DPO: SFT `0.1244 → 0.1093` → **reject**
- 최종 post-training 선택: **SFT adapter**
- Claude Judge: synthetic positive/negative 분리 확인; 의료진 평가나 임상 검증 아님

좋아진 결과만 남기지 않고 timeout·회귀·미채택 결과도 기록합니다.

## 6. 지원서에서 말할 수 있는 것 / 없는 것

### 말할 수 있는 것

- FastAPI 기반 실시간 기록 workflow를 독립 설계·구현하고 실제 Render에 배포했다.
- 배포 중 packaging failure와 live semantic bug를 발견해 regression test와 deployment smoke로 재발을 막았다.
- PostgreSQL/Redis 실서비스 경로를 CI에서 검증하고, public demo의 SQLite/memory 경로는 운영 화면에 사실대로 표시했다.
- LLM 출력에 evidence, human review, purge lifecycle을 연결했다.

### 말하면 안 되는 것

- `AWS 운영 경험이 있다` → **없음. Terraform 설계 시작점만 있음.**
- `의료 AI를 임상 검증했다` → **아님. synthetic portfolio evaluation임.**
- `실제 환자 상담 데이터를 처리했다` → **아님. 합성·비식별 데이터만 사용.**
- `DPO로 모델을 개선했다` → **아님. gate에서 reject됨.**
- `full semantic RAG가 더 좋았다` → **아님. 현재 regression set에서 미채택.**

## 7. 남은 실무 경험의 빈칸

프로젝트 완성과 별개로 다음은 입사 후 배워야 하는 영역입니다.

1. 실제 AWS 계정에서 ECS/RDS/ElastiCache 운영과 비용·장애 대응
2. 인증/인가, 다중 테넌시, KMS/secret rotation
3. WebSocket drain/autoscaling과 production traffic 관측
4. 실제 마이크·억양·배경 소음 환경의 STT 검증
5. 실제 의료 데이터 governance와 조직 내부 보안/심사 절차

지원 전략은 이 빈칸을 숨기는 것이 아니라, **작은 기능부터 로그·테스트·배포 결과로 확인하는 백엔드 개발자**로 설명하는 것입니다.
