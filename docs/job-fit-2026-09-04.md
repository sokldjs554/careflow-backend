## 현재 실험 증거

### Clinical Note live E2E

- `scripts/live_claude_check.py`를 실제 Anthropic API로 실행
- generator: `anthropic-claude-sonnet-5-sop-v1`
- 단일 합성 API contract check latency: `5217.679 ms`
- Subjective는 환자 발화 `[1, 2]`, Objective는 관찰 발화 `[3]`, Plan은 의료진 계획 발화 `[4]`에 evidence 연결
- JSON Schema structured output과 evidence contract 모두 통과
- 이후 Codespaces Review Workspace 정상 합성 시나리오에서 `WebSocket text → Claude S/O/P → evidence gate → READY → transcript purge`까지 실제 확인
- UI finalize latency: `6770 ms`
- S/O/P evidence badge가 각각 `#1/#2`, `#3`, `#4`에 연결됨
- `Assessment`는 JSON Schema/Pydantic 경계에서 차단
- DB / Transcript store `healthy`, Purge `purged`
- audit timeline에서 `session.finalized`, `transcript.purged` 확인
- 상세 기록: `docs/live-e2e-2026-09-04.md`
- 합성 정상 시나리오 1건의 live 검증이며 평균 latency나 임상 품질로 일반화하지 않음

### RAG

같은 synthetic retrieval holdout에서 다음을 비교했다.

| 방식 | Recall@5 | MRR | nDCG@5 |
| --- | ---: | ---: | ---: |
| Qdrant hashing smoke | 0.9375 | 0.8750 | 0.8518 |
| lexical TF-IDF | 1.0000 | 0.9375 | 0.9385 |
| hybrid + smoke rerank | **1.0000** | **1.0000** | **0.9746** |
| BGE-M3 + CrossEncoder | 0.9375 | **1.0000** | 0.9416 |

BGE-M3 + CrossEncoder는 실제 모델 다운로드 경로까지 실행했지만, 현재 작은 synthetic regression set에서는 hybrid smoke보다 Recall@5와 nDCG@5가 낮았다. 따라서 **구현했다는 이유만으로 채택하지 않고 현재 미채택**으로 기록한다. 더 큰 허용 데이터셋에서 재평가한다.

### SFT / DPO

- 합성 학습 계약: SFT 120건 / DPO preference 120쌍
- Base / SFT / SFT+DPO를 같은 holdout으로 비교
- SFT gate: safety 회귀 없음 + unsupported number 회귀 없음 + reference token F1 `+0.02` 이상
- SFT gate 통과 전에는 DPO 성능을 주장하지 않음
- 실제 Qwen2.5-0.5B CPU LoRA 실험 workflow를 별도로 두어 파이프라인 코드와 실제 학습 실행을 구분
- 첫 CPU LoRA 학습은 96 train / 24 validation, 1 epoch로 실제 완료했으며 train loss `2.465941`, eval loss `2.168`, eval mean token accuracy `0.5569`를 기록
- 첫 Base↔SFT 생성 비교는 Transformers 5 `BatchEncoding` 호환 버그로 실패해 evaluator를 수정했고, corrected holdout gate를 재실행 중

### Multimodal

- EMA-only / Text-only / Fusion 비교
- ROC-AUC / F1 / Brier
- synthetic 결과는 임상 성능으로 해석하지 않음

### Evaluation

- deterministic contract gate: Evidence 존재, unsupported number, 금지 진단/처방 표현
- Claude Sonnet 5 live LLM-as-a-Judge: synthetic positive 3건 + negative 3건 실제 API 평가
- positive 평균: groundedness `5.000`, completeness `4.333`, safety `5.000`, clarity `5.000`
- negative 평균: groundedness `1.000`, completeness `2.000`, safety `2.000`, clarity `3.333`
- 전체 평균은 3점대지만, 실패 예제를 의도적으로 절반 포함했기 때문에 품질 평균으로 해석하지 않음
- 원문에 없는 기간 추가는 groundedness `1`, 임의 진단/증량 권고는 groundedness `1` 및 safety `1`로 낮게 판정
- 결과 파일: `ai/results/llm-judge-live.json`
- 전문의 평가가 없는 상태를 명시하며 임상 검증으로 표현하지 않음

## 채택 원칙

1. 모델 이름이나 기법 사용 여부가 아니라 같은 holdout의 결과로 판단한다.
2. 안전성·근거성이 회귀하면 성능 지표 일부가 좋아져도 채택하지 않는다.
3. 합성 데이터 결과를 임상 정확도나 실제 환자 성능으로 표현하지 않는다.
4. 실패하거나 미채택한 실험도 README와 결과 파일에 남긴다.
